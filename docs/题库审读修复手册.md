# 题库审读修复手册（2026-11-07 三轮实战沉淀 · 可复用运行手册）

> 适用场景：发现题目缺陷要修、扩容后要核验、定期巡检、换题库重新审读。
> 本手册是三轮全库实战（488 条修正落库、零删除、学生记录零断链）的完整沉淀——
> 下次照着跑即可，不用再摸索。工具全部在本仓库 `tools/`，证据规范在 `evidence/qbank-audit/`。

## 〇、铁律（违反会破坏学生数据或题库质量）

1. **qid = djb2(m|qt|s)，题干参与计算**：改题干 = 改 qid。任何 s 字段修改必须经
   `apply-v5fix.js`（自动登记迁移）落库，映射由 `tools/qid-migrate.js` 维护进
   `window.XK_QID_MIGRATE`，读档自动迁移——**学生记录零断链是底线**。
2. **难度不得加难**：中职基础题库。改写选项/解析只准复用同族题现成词汇与表述，
   禁止引入新概念、新场景、更技术化的说法（用户硬性要求）。
3. **优先修改不删**：只有「完全无法救回且强误导」才删，且删除需人工确认（三轮实战 0 删除）。
4. **只动 `src/data.js` 真源**，产物（dist/site/pk 独立版/桌面副本）一律重新构建同步，禁止手改。
5. **不提交密钥**：`cloud/keys.json` 已 gitignore；提交前 `git status` 检查。
6. **宁缺毋滥**：代理只报 100% 确信的问题（实测健康区间 0.7%~3%/千题；报 60+ 条就是标准太松）。
7. 部署凭据不回显；teacherKey/classCode 只经环境变量或服务端使用。

```
你是中职《信息技术基础》学科审题专家。项目根目录：C:\Users\Administrator\Desktop\信息技术基础\学考冲刺通
逐题审读【N】题（i=【起】~【终】），材料：evidence/qbank-audit/chunks-xxx/partK.json（用 Read 读完，不许抽样）。
字段：i(当前下标,原样引用)/m/kd/qt(单选|判断|多选)/s/o(判断题固定√×)/a/e。
审查维度：①答案学科事实正确性(field=a,最重要,100%确信才报) ②解析与答案矛盾/解析串题(field=e,fix=完整替换解析60~200字)
③选项缺陷(field=o,重复/截断/答非所问;fix=完整选项数组JSON串,判断题o不动) ④题干事实错误(field=s,保留「（ ）」;题干残留选项列表已根治勿报)。

⚠「选正确/选错误」变式题对的答案可能被生成器互换——用解析原文结论+同族镜像题双重印证。
输出：Write 到 evidence/qbank-audit/v5fix-<批次>.json，JSON数组，无发现写[]。最终回复：实读题数/发现分布/最有把握2条/未改其他文件声明。
```

### 模板 B：遗留缺陷专项修复（按清单分组，组间按索引区间切分避免撞题）
```
你是审题修题专家。修复 evidence/qbank-audit/chunks-v9/gK.json 里的【N】题（Read 读完）。
缺陷类型与修法：
①解析主题错位（整段讲同族他题）→ field=e 围绕本题题干与答案重写(60~200字,简单直白)。
②歧义「选错误」题（多个错误选项无唯一解）→ field=o 把多余错误选项改写成同族**正确**说法，
  只留原答案一个该错项（**答案字母保持不变优先**）；fix=完整选项数组 JSON 串。
③「以上都是」式无意义选项 → 换同族简单、具体、真的说法。
④题干漏字/错别字/杂散前缀 → field=s 完整替换题干（保留「（ ）」）。
⑤解析结论字母与答案矛盾 → field=e 重写。
铁律：难度不得加难（复用同族现成词汇,禁止新概念新场景）；宁缺毋滥,清单是凭记忆列的可能有出入,没缺陷就跳过；
答案修改需 100% 确信+证据；除输出文件外不得修改任何文件。
输出：evidence/qbank-audit/v9-gK.json，最终回复：实读/修复数/分布/最有把握2条。
```

### 模板 C：疑难核验要点（给代理的提示，也给自己）
- 同族题互证：库里兄弟题的题干/解析是判定变式题答案的最硬证据（如 i=1935 原句=干扰项 → i=1939 必错）。
- 解析原文结论 vs 记录答案矛盾 = 生成器残留的直接证据。
- 判断题解析残留「因此选B/选D」、单选残留「因此选ABCD」＝模板未清理标志。
- 教材口径争议（CPU 组成、加密算法分类边界）不报不修；同族口径冲突要统一到通行说法并全族一致。

## 四、实战经验（三轮 488 条修正的教训，条条踩过）

1. **并发 4 路安全，5 路易撞配额**：`user concurrency limit exceeded` 等跑完的结束后补跑即可，任务无损坏。
2. **a 类（改答案）是最高风险项**：必须人工逐题看选项真值，代理证据（解析原文/镜像题）只作参考不作放行。
3. **清单误报正常**：凭记忆列的清单会有一成左右出入（如 i=1323 实为唯一解）——代理「没缺陷就跳过」的指令必须保留。
4. **apply-v5fix 三个坑**（已修，勿回退）：会丢 XK_QID_MIGRATE 行→已改保留；s 改名不留映射→已自动登记；
   与历史考古方向相反的改名会产生 A→B→A 回摆环→已加打破逻辑。
5. **data.js 尾部新增全局语句（如 MIGRATE）会让旧解析器 500**：班级版服务.py 与 cloud/worker.js
   都必须「window.BANK= 行内提取」（契约测试在 tests/qid-migrate.test.js）。
6. **qid-migrate 必须幂等可重跑**：重跑要沿用既有映射（自检清洗+链解析到终值）、证据清单丢失要能从
   已提交版本重建、无变更不重写文件——否则重跑一次丢一次证据。
7. **映射淘汰宁缺勿错**：错误映射会把学生记录挂到别的题上，比不映射危险得多；淘汰条目考古会重推。
8. **线上测试绝不写云端数据**：e2e-full.js 对线上只取消学号弹窗不登录（sid 为空前端不发起同步）。
9. **SSH 推送瞬断**（github.com:443 走 github-xuekao）：`git push` 失败先重试 2~3 次再诊断。
10. **构建守卫不要绕**：build.js 的 ID 唯一/考纲 150 校验、pk-build 三道守卫、gen-* 防递归守卫都是保护机制。
