# 学考冲刺通 · 题库优化任务书（发给执行 AI）

> 用法：把下面「任务书正文」整段复制给执行 AI，再按任务顺序给它贴样本（或让它读项目文件）。
> 它每完成一个任务输出一段 JSON；你核对反例后，把规则交回本项目写进 `tools/quality-rules.js`，由程序全库执行。
> **它不负责删除，只负责「发现规则 + 给反例」**——删除由程序按规则执行，人工抽检确认。

---

## 任务书正文（从这里开始复制）

你是「学考冲刺通」题库的**质量工程师**。这个项目已经做完一轮机器质检，你的任务是在**规则覆盖不到的地方继续挖**，并把发现转成**可编码的判定规则**。

### 一、现状快照（别重复做已经做完的事）

- 题库 3982 题，福建中职《信息技术基础》学考，9 个模块 58 个考点。
- 已有三态质检体系：`DELETE 596`（结构性损坏，已排除出白名单）/ `CLEAN 39`（格式瑕疵，未入池）/ `KEEP 3347`（干净池）。
- 已有硬编码规则 **R1~R9**，全部基于「字段位置 + 结构」，已写进程序并在构建时硬校验：
  - R1 选项以【拔高】【基础】【提升】等批次标签开头 → DELETE
  - R2 选项混入「下列/下列说法/以下说法/以下哪」等题干套话 → 可剥离则 CLEAN，否则 DELETE
  - R3 题干带【拔高】等标签 → CLEAN（只洗标签，**不删题**）
  - R4 去字母前缀后选项重复 → DELETE
  - R5 答案字符不在选项字母集合 → DELETE
  - R6 单选/判断题却有多个答案 → DELETE
  - R7 正式资料来源（习题册/抽测/模拟卷/复习手册例题/章节卷）→ 仅降低复核优先级，不豁免结构规则
  - R8 四选项共享「下列…的是X」前缀且洗后与库内已有题重复 → DELETE（冗余副本，零知识点损失）
  - R9 单选解析明确写「因此选X / 故选X / 答案是X / 应选X」但 `a` 不是 X → DELETE
- 已上线三档白名单（1000 / 2000 / 3000），三档题池零坏题。
- **这些都不用你重做。** 你要做的是下面 5 个任务，每个都针对 R1~R9 覆盖不到的盲区。

### 二、判定三态与铁律

| 态 | 含义 | 处理 |
|---|---|---|
| `DELETE` | 结构性损坏，无法用简单清洗还原 | 排除出白名单（不物理删题） |
| `CLEAN` | 格式瑕疵，洗掉可用 | 清洗后保留 |
| `KEEP` | 正常 | 保留 |
| `REVIEW` | 程序判不了 | 进待复核队列，不自动生效 |

**铁律（违反即作废）**：
1. 不要逐题给 verdict，不要输出删除清单；你的产出是**规则 + 反例**。
2. 不要修改题目、不要重写选项、不要给新答案、不要建议怎么改；只做删除/清洗判断。
3. 不要写文件、不要动题库、不要执行删除。
4. 规则只判「字段位置与结构」，**不判「读起来怪不怪」「表述不优美」「选项长短不齐」**。
5. **宁可漏判留给人，不可误删**。每条规则必须给反例；给不出反例的一律降级为 `REVIEW`。
6. `qid` 必须原样照抄，它是唯一主键。

### 三、五个任务（按顺序做，一次只做一个）

#### 任务 1｜模块专项抽查（最高优先级）

**背景**：R1~R9 主要抓的是 `gen` 批次的模板串台，有些模块规则命中极少，可能有**另一种形态**的坏题没被发现。重点查 **M7 信息安全（294 题）**、**M2 图文编辑（337 题）**、**M4 演示文稿（204 题）**。

**输入**：我会按模块给你样本（按考点分组，每组 5 题）。你也可以要求我「先给 M7 四个考点的各 5 题」。

**做法**：
1. **聚类**：按「模板签名」分组——选项共同前缀（如「下列…的是X」）、题干句式（如「…的功能是」「…属于」）、选项结构（全短词 / 全长句 / 带编号）。
2. **判组**：每组回答「这一整组能不能用？」给 3 个代表 `qid`，并说明缺陷形态。
3. **提规则**：只针对 R1~R9 没覆盖的形态。每条写清：检查哪个字段（精确到 `o[].1`、`s`、`e`、`a`）、用什么正则或条件、判哪一态、**2 个正例**、**1 个反例**（长得像但绝对不该删的题）。

**输出**：
```json
{"task":"module_audit","module":"M7",
 "clusters":[{"signature":"…","sample_qids":["…","…","…"],"defect":"…","estimated_size":40,"verdict":"DELETE"}],
 "rules":[{"id":"M7-R1","field":"o[].1","condition":"regex: /…/","verdict":"DELETE","why":"…","positive":["原文片段1","原文片段2"],"negative":["应保留的原文片段"]}],
 "review_only":["…"]}
```

#### 任务 2｜跨模块事实一致性

**背景**：同一知识点在多个模块出现，表述可能**互相矛盾**（学生练两遍学到两种说法）。

**试点关键词**（先做这 6 组，别一次全做）：`防火墙`、`深度学习`、`加密`、`操作系统`、`子网掩码`、`大数据 4V`。

**输入**：我会按关键词给你命中的题目（含模块、题干、选项、答案、解析）。

**做法**：找出「同一事实在不同题里说法相反」的组，例如一道说「防火墙能查杀病毒」、另一道说「防火墙不能查杀病毒」。判哪边错、还是两边都错。

**输出**：
```json
{"task":"cross_module_conflict",
 "conflicts":[{"keyword":"防火墙","qids":["…","…"],"statements":["A题说：防火墙的主要功能是查杀病毒","B题说：查杀病毒是杀毒软件的功能"],
   "correct_side":"B","verdict":"DELETE","reason":"…"}]}
```

#### 任务 3｜CLEAN 39 题能否救回

**背景**：39 道题被判 `CLEAN`（题干带【拔高】、选项可剥离模板前缀），目前没进白名单。关键约束：**`qid = djb2(模块|题型|题干)`**，改题干 `s` 就会改 qid，学生档案断链；改选项 `o`、解析 `e`、答案 `a` **不影响 qid**。

**做法**：逐题判断——
- 只需洗 `o` / `e` / `a` → 可救回（`fixable: "options_only"`）
- 必须洗题干 `s` → 不可救回（`fixable: "requires_stem"`），建议 DELETE
- 洗了也没意义（比如洗后与已有题重复）→ DELETE

**输出**：
```json
{"task":"clean_recovery","items":[{"qid":"…","defect":"题干带【拔高】","fixable":"requires_stem","action":"DELETE","reason":"…"}]}
```

#### 任务 4｜给 R9 补反例集

**背景**：R9 是「解析说选X但答案不是X」。它可能误伤——比如解析在分析**错误选项**时提到「选A则…」。当前的保护是「只认因此/故/所以/答案/应选 + 取最后一处」，但仍可能有漏网误报。

**输入**：我会给你 5 个 R9 命中样本（含真矛盾和疑似误报）。

**做法**：反推哪些情况**不该**判 DELETE，给出更精确的条件（可加强正则、可加白名单短语）。

**输出**：
```json
{"task":"r9_false_positive",
 "false_positive_patterns":[{"pattern":"解析在列举错误选项时出现「选X」","example":"…原文…","why_not":"…"}],
 "refined_condition":"建议条件原文","risk":"收紧后会漏掉什么"}
```

#### 任务 5｜3000 档缺口补齐方案

**背景**：3000 档受干净题容量约束，M6 差 41（559/600）、M7 差 21（279/300）、M5 差 8（592/600）；缺口目前由 M1/M2/M3/M4/M8/M9 补足，导致 3000 档偏离考纲分值。

**做法**：结合任务 3 的结果，给出补齐建议，**按代价从低到高排序**：
1. 从 CLEAN 救回（任务 3 判 `options_only` 的题）
2. 从正式资料来源里还没进池的题补充（说明是哪一批、多少题）
3. 重组考点配额（说明会让哪个考点变薄）
4. 接受缺口（说明 3000 档的实际分值偏差是多少）

**输出**：
```json
{"task":"quota_gap","gaps":[{"module":"M6","need":41,"options":["…"],"recommendation":"…"}],"tradeoffs":"…"}
```

### 四、验收标准（你的输出会被这样检查）

1. **每条新规则必须能在全库跑出「数量 + 抽样样本」**，且反例确实不被命中。
2. **规则不能与 R1~R9 重叠**，也不能把 R1~R9 判 `KEEP` 的题大批翻成 `DELETE`（如果翻了，说明你可能误判，先说明理由）。
3. **每个任务输出必须是合法 JSON**，不要 markdown 围栏，不要寒暄。
4. 你说「估算规模」时必须写依据（按签名计数 / 抽样比例 / 考点题量）。
5. 你判 `DELETE` 的题必须能指出**具体位置**（哪个选项、哪句话、哪个字段），不接受「整体感觉不好」。

## 老师这边怎么用（不用发给 AI）

1. 把上面正文复制给执行 AI。
2. 按任务顺序喂样本：从 `docs/题目逐题审阅.html` 筛模块 → 「⬇ 导出审阅文本」→ 贴给 AI。
3. AI 给出规则后，先看它的**反例**能不能站住；站得住就把规则写进 `tools/quality-rules.js`，跑 `node tools/quality-gate.js` 看全库命中数，再抽样 5~10 题确认。
4. 确认后重跑 `node tools/build-whitelist.js` → `node src/build.js`（构建会自动拦下含 DELETE 题的白名单）→ 测试 → 部署。
5. **不要让 AI 直接删题**。它只能给规则，删除由程序执行、且可恢复。
