# 客户端模式壳层升级计划（2026-11-07 定稿）

> 教师确认两条：①「输入学号」弹窗**保留现状**（不做选名字改造）；
> ②客户端模式下底部 tab **换成上课用的那组**（PK / 擂台等），而不是网页的「首页/刷题/错题/诊断/PK」。
> 教师疑问「客户端是不是要重写」——结论：**客户端本体（托盘+本地服务+窗口）不重写**，
> 只给网页层加一个「客户端模式壳」，一个提交交付；网页端行为 100% 不变。

## 一、客户端底部 tab 组（定稿）

| 顺序 | tab | 落点 | 说明 |
|---|---|---|---|
| 1 | 🏠 首页 | #/home | 预估分/入口卡/荣誉榜（现首页原样） |
| 2 | ⚔️ 双人 PK | #/pk | 现 PK 页 |
| 3 | 🥊 擂台赛 | #/arena | 现擂台页 |
| 4 | 📋 备课夹 | #/prep | **新独立页**：备课夹管理卡从首页复用渲染（勾题/清单/清空） |
| 5 | 🎲 课堂互动 | #/class | **新独立页**：名单管理 + 随机点名 + TTS 音色（课堂互动卡复用渲染） |

对比网页 tab（首页/刷题/错题/诊断/PK）：客户端把「上课三件套」PK/擂台/备课夹 +
点名提到一级导航；刷题/错题/诊断仍从首页入口卡进（教师叫学生上台刷题时走首页）。

## 二、模式判定与生效范围

- 启动器打开窗口时 URL 带 `?client=1`（launcher.cs 一行改动）；
  页面读取后写入 `localStorage.xkc.client='1'`，刷新/后退保持。
- 生效条件：`body.client` 类 + 底部 tab 栏渲染客户端组；**网页端（无标记）行为零变化**。
- 兜底：客户端 exe 启动参数带标记，若教师用浏览器直开 127.0.0.1:8953（无标记）→ 网页模式。

## 三、对战中隐藏规则（沿用既定决策）

PK/擂台**对战进行中**（running）→ 底部 tab 栏隐藏（投屏一屏高度让给题目）；
退出对战/结算后 tab 栏回归。顶栏 ←→ 导航按钮在对战中始终可用。

## 四、技术设计

1. **两个新面板**（不挪动首页卡片，双渲染复用）：
   - `#prep`（备课夹页）+ `#class`（课堂互动页）：markup 各放一份同构容器（id 加 `2` 后缀），
     renderPrepMgr / renderClassroom 改为「渲染到存在的所有容器」（循环两份 id）；
     事件绑定同样双绑。首页卡片保留（网页端用户照旧）。
2. **客户端 tab 栏**：复用现有 .tabs 底栏容器，`body.client` 时由 JS 渲染客户端五项
   （.tab[data-t] 同构，data-t 取 home/pk/arena/prep/class）；非 client 模式渲染原五项。
3. **路由扩展**：TABS 加入 prep/class（客户端模式才生效）；navPush/routeTo/hash 路由直接支持。
4. **launcher.cs**：`--app=http://127.0.0.1:8953/?client=1`（一行）。
5. **学号弹窗**：保留现状——客户端模式下照常弹（与本地数据库归属逻辑一致，不重做）。

## 五、实施步骤（单提交）

1. launcher.cs URL 加 `?client=1`
2. app.js：模式检测 + 客户端 tab 渲染 + TABS 客户端扩展 + prep/class 双渲染改造
3. build.js 模板：#prep / #class 两个面板骨架（复用卡片内容）
4. E2E：client 模式（URL 带 query）→ tab 组断言（PK/擂台/备课夹/课堂互动）→
   备课夹页勾题 → 课堂互动页点名 → 对战中 tab 隐藏回归 → 网页模式无变化回归
5. `node tools/build-client.js` 重打包 → 安装包 `--silent` 更新本机客户端 → 启动实测
6. changelog/HANDOFF/biji-notes 交接
