## 0. 一句话说清这是什么

双人 PK 是「一局定胜负」；擂台赛是**一人守擂、全班轮流踢馆**：赢家坐擂位，系统给出 3 个候选挑战者，教师点一个上台，再打；平局算擂主守住；打满 N 场自动结算最终擂主。

---

## 1. 目标 / 非目标

**目标**

1. 课堂上投屏一开，**0.5 秒内就能看出这是擂台赛、不是双人 PK**（配色 + 图标 + 版式三重区分，不靠文字标签）。
2. 教师只做一个决定：点哪个候选上台。其余全自动。
3. 一节课（40 分钟）能跑完 12-15 场。
4. 与双人 PK 数据完全隔离，误操作不会污染已有战绩与总排行榜。

**非目标（本轮明确不做，避免范围膨胀）**

- 不做学生手机应擂（擂台是投屏活动，学生端不参与）。
- 不做跨班联赛、不做时间线动画、不做音效包下载。
- 不改双人 PK 的任何默认值、布局、文案、音色策略。
- 不做独立版 `pk/dist` 的擂台入口（合并版验证过再议）。

## 2. 与双人 PK 的硬隔离

| 维度 | 双人 PK（不动） | 擂台赛（新增） |
|---|---|---|
| 容器 | `#pkPage` / `#pkArena` | `#arenaPage` / `#arStage` |
| 元素 id 前缀 | `pk*`、`btn*` | **一律 `ar*`**（如 `arChamp`、`arGo`） |
| 存储 | `pk.cfg` `pk.roster` `pk.matches` `pk.snd` | **`pk.arena.v1` `pk.arena.cfg`**（名单与音效**读** `pk.roster`/`pk.snd`，不写） |
| 样式 | `pk-style.css` | **`arena-style.css`**，选择器一律 `.ar-*` |
| 逻辑 | `pk-app.js` → `window.__PK_MOUNT` | **`arena-app.js` → `window.__ARENA_MOUNT`** |
| 文案 | `XKP` 表扬语 | **`window.XKA` 擂台语料**（新增 `arena-lines.js`）+ 单题反馈仍用 `XKP` |
| 入口 | 首页「⚔️ 双人 PK」卡 + 底部 PK 页签 | 首页新增「🥊 擂台赛」卡，**不加底部页签** |

**为什么用两套 id 而不是复用**：复用 id 意味着同一份 DOM 里两套逻辑抢元素，是"改坏原来功能"最常见的入口。前缀互斥之后，任何一边误读另一边 id 会当场拿到 `null` 报错，而不是静默出错——宁可崩在测试里，不要错在课堂里。

## 4. TTS 差异化（含实测数据）

**实测这台机器**：`speechSynthesis.getVoices()` 共 3 个声音，全是中文本地声：

```
Microsoft Huihui   zh-CN  女
Microsoft Kangkang zh-CN  男
Microsoft Yaoyao   zh-CN  女
pitch / rate 均支持（规范范围 0-2 / 0.1-10）
```

**方案**（四层叠加，任一层单独都不可靠，叠起来才"听得出"）：

| 层 | 双人 PK（现状） | 擂台赛 |
|---|---|---|
| 音色 | **随机**抽一个中文声 | **固定 Kangkang**（男声），取不到时退回中文声列表第 0 个 |
| 音调 | 默认 `pitch=1` | `pitch=0.8`（更低沉） |
| 语速 | 默认 `rate=1` | `rate=0.92`（放慢，有"报幕"感） |
| 结构 | 「请 X、Y 上台对战！」 | 「**现在打擂台。擂主 X，已连胜 N 场。挑战者 Y，上台！**」——先报擂主再报挑战者，句式和 PK 完全不同 |
| 音效 | 上行三音（523/659/784Hz） | **鼓点式**：低频两下（110Hz、110Hz 短）+ 高音一下（440Hz），另配「击落」音（下行两音） |

**必须说清的三个坑**

1. **重叠概率**：PK 是随机音色，约 **1/3 场次也会抽到 Kangkang**，那几场听起来会像擂台。彻底解决要么让 PK 排除 Kangkang（**改动现有行为，我不建议**），要么接受重叠。→ 需要你表态。
2. **跨机器差异**：教室投屏机可能只装了 1 个中文声（甚至 0 个）。所以擂台 TTS 必须写成"**优先 Kangkang，取不到就用现有声 + pitch/rate 偏移**"，绝不因为找不到指定声音而不出声。
3. **首声静默**：浏览器要求用户手势后才允许发声。擂台页第一次点「开始这一场」就是手势，够用；但**候选席上的"试听"按钮**要单独提示一次，否则教师会以为没声音。

## 7. 状态机与规则

```
idle ──点「开始这一场」──> running ──双方答完/时间到──> judging ──┬─> running（还有场次）
                                                        └─> finished（满 N 场）
```

- **擂主来源**：第 1 场由系统从候选袋抽 2 人先打（无擂主）；之后胜者进 `champ`。
- **候选袋**：`queue = shuffle(名单 - 当前擂主)`，每场取 3 个当候选；被点者出袋；袋空 → 重洗并提示。
- **每场**：擂主在左、挑战者在右，同批题各自乱序（沿用 `XK.pickFromBank` 的章节过滤）。
- **判定**：`score` 高者胜；**平局 → 擂主守住**（挑战者算落败，回座位并记一场）。第 1 场平局 → 抽加赛一场（因为此时没有"守方"）。
- **计时到点**：以已答题数定胜负；都没答完则判平局（同规则）。
- **满 N 场**：`finished`，出结算面板 + 播报；擂主与连胜写入 `pk.arena.v1`。

## 13. 落地后的两处返工（都是截图才看出来的，单测当时全绿）

**返工 1：一屏自适应"缩了个寂寞"**
`fitToBox` 只把 `--pkfs` / `--arfs` 往下调，但选项内边距、ABCD 圆片、姓名/分数、提交按钮
全是固定 px —— 缩字号几乎不缩总高。实测 1366×768：**随机 200 题里 170 题（85%）顶到 16px
下限并开滚动**，最长 20 题 100% 溢出。
改法：把面板里所有"占高度的零件"改成 `calc(var(--pkfs) * k)` / `calc(var(--arfs) * k)`。
改完实测（`node tools/gate-fit.js 1366 768 400`）：

| | 面板可用高 | 随机 400 题中位字号 | 随机需滚动 | 最长 20 题需滚动 |
|---|---|---|---|---|
| 返工前 | 508px | — | 85% | 100% |
| 返工后（PK） | 508px | 21px | 1 题 = 0.3% | 3 题 = 15% |
| 返工后（擂台） | 496px | 22px | 0 题 = 0.0% | 2 题 = 10% |

闸门：`tools/gate-fit.js`（浏览器实测）+ `pk-features` 两条 CSS 结构断言 + `arena` A7。
把 CSS 退回固定 px 版本再跑，三条断言确实全红（44→42、27→26）。
