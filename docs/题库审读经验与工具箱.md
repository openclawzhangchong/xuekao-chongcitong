## 一、五大系统性缺陷（变式题生成器的病根，已全部修复进 tools/gen-variants.js）

| # | 缺陷 | 根因 | 已落的修复 |
|---|---|---|---|
| ① | **按关键词落 key**（正反两题 key 同错，52 处答案错标） | 变式生成按母题答案字母落位，不按整句真值 | 生成后自检闸门（见下）＋ R14 正反冲突检测 |
| ② | **组合选项重排未重映射**（「A和C」悬空，8+19+52 题报废） | 多选拆项时组合项文本当普通陈述塞进选项 | BAD_FILL 扩充：`[A-D]\s*[和与及]\s*[A-D]` 不入池 |
| ③ | **双错误项变式→双解**（M7 27 例、M5M6 52 例爆发） | borrowCorrect 借池借到假命题（陈述池污染：矛盾陈述同时进真假两池） | pushStmt 真值锁（`stmtTruth` Map：同一陈述禁止同时进 correct/wrong 池） |
| ④ | **解析复制母题**（~90% 变式解析不解释本题主旨，61+ 处「因此选X」指错字母） | 变式 e 直接复制母题 cleanE | mkQ 层解析模板化：母题知识点句＋按最终 key 生成结论句「（变式解析：本题正确说法是「X」，故选Y。）」 |
| ⑤ | **反转句式未改净**（选项嵌「以下不是…的是」套话） | 陈述池入池时未过滤嵌套题干套话；cleanE 正则坏（`选s*` 丢反斜杠→「因此选X」过滤全失效） | 修 cleanE 正则；BAD_FILL 扩充 `以下[^，。]{0,16}(不是|属于)…的是`；R2 的 CLICHE 加「以下不是」 |

**生成器加固三件套**（tools/gen-variants.js）：
1. cleanE/正则修复；
2. 陈述池真值锁＋BAD_FILL 扩充；
3. **自检闸门**：输出前对全部生成题跑 `tools/quality-rules.js` 三态分类，非 KEEP 一律剔除——下次再跑生成器，五类缺陷题到不了题库。

## 三、审读代理调度经验（实测）

1. **并发上限 ~3**：6 个齐发会 "user concurrency limit exceeded" 全灭，2-3 个稳妥；失败的等位重发即可。
2. **代理 JSON 必须带 `m/qt/i` 字段**：qid 会被代理算错（库并行演进时下标错位），`apply-agent-fixes.js` 用 i＋m/qt 交叉校验。
3. **代理报的 qid 可能笔误**：以 i 下标对库内 `XK.qidOf` 重算为准（M5M6 三例）。
4. **代理审读期间库会被并行修改**：要求代理"对当前库逐条校验"（M9 代理的经验），或接受其按快照审读+落地时以 i 对账。
5. **每个代理的 prompt 必须带**：模块知识点清单（判事实对错用）、已知缺陷模式清单（变式四型）、分级铁律（fix 需 100% 把握附证据/uncertain 不猜/delete 仅限双解无解重复）、输出 schema（含 m/qt）。
6. **落地节奏**：代理返回一批就落地一批（apply-agent-fixes → apply-v5fix → build-whitelist → build site → 单测），不要攒——库版本漂移会让旧清单失效。

## 四、审读判定经验（哪类问题藏在哪）

1. **判断题是重灾区入口**：511 题全量人工审一遍成本可控（分 4 批 dump），事实方向错误全在这里。
2. **gen 变式区间集中**：按 src 标签（gen:fallback/fwdJudge/multiSplit/judgeWrong/revCorrect）与题干模板签名（【考点名】（N）下列说法正确的是）聚类，一抓一串。
3. **完全重复判据**：规范化题干（去【标签】去空白）＋选项集合排序拼接，两者都同才算重复；只看题干会误伤泛题干（「下列说法正确的是」）。
4. **答案偏斜检测**（考点内某字母 ≥85%）可发现模板题，但正常模块为 0——可作为巡检项。
5. **跨模块错挂**：内容主题词（安全/AI）测选项而非仅题干——M9 考点 11 的 160 题错挂里 100+ 题题干带【大数据】标签但选项是安全/AI 内容。
6. **题干含答案事故**（「正确的是XXX」后面直接跟答案）用正则 `，正确的是[^（(]` 一抓一个准。
7. **信息规则 vs DELETE**：句式病态但可作答的（首项「以上/以下」、选项复制题干）判 KEEP+rules 标记留人工；结构硬伤（双解/无解/占位符/判断格式残留/正反 key 冲突）判 DELETE。宁可漏判留给人。
