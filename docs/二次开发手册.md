### 双形态

|---|---|---|---|

## 六、qid 迁移系统（学生记录零断链）

### 原理

qid = djb2(m|qt|s)。**题干参与计算**——改题干 = 改 qid。迁移映射 `window.XK_QID_MIGRATE`
（嵌入 data.js）记录旧 qid → 新 qid 的映射。engine.js 的 `migrateProfileKeys` 在读档时自动重命名。

### 改题干的正确流程

```bash
# 1. 用 apply-v5fix.js 落库（s 字段改动自动登记迁移）
node tools/apply-v5fix.js v10-fix-pX.json

# 2. 重跑迁移自愈（合并新旧映射、清理回摆环）
node tools/qid-migrate.js

# 3. 验证
node tests/qid-migrate.test.js
```

### 禁止事项

- ❌ 直接改 src/data.js 的 s 字段（绕过迁移登记 → 学生记录断链）
- ❌ 删除 XK_QID_MIGRATE 行（旧记录无法恢复）
- ❌ 在迁移映射中制造 A→B→A 回摆环

## 七、题库审读修复流程

### 7.1 全流程

```
生成快照 → 派审读代理 → 合并校验 → a 类亲核 → apply-v5fix 落库 → qid-migrate 自愈 → 闸门 → 构建部署
```

### 7.2 快照生成

```bash
node tools/gen-audit-chunks.js 0 3982 250   # 全库 250 题/块
node tools/gen-audit-chunks.js 0 1000 250 evidence/qbank-audit/chunks-xxx  # 指定范围
```

### 7.3 审读代理提示词模板

见 `docs/题库审读修复手册.md` §7.2（三个模板：审读/专项修复/疑难核验）。

### 7.4 并发策略

- **4 路并发**实测可用（250 题/代理，6~15 分钟/个）
- **5 路会撞限**（`user concurrency limit exceeded`）——等跑完的结束后补跑
- **串行 1 路**最稳但最慢（18 分钟/250 题）

### 7.5 修复落库

```bash
# 合并各代理产出
cat evidence/qbank-audit/v10-fix-p*.json | python -c "..." > v10-all.json

# 结构校验（索引/field/o 数组合法性/a 在选项中/e 长度）
node tools/check-frag.js  # 或自行校验

# 落库
node tools/apply-v5fix.js v10-all.json

# qid 映射自愈（如有 s 字段改动）
node tools/qid-migrate.js

# 回归
for t in qid-migrate engine classroom pk-pick pk-features arena; do node tests/$t.test.js | tail -1; done
node tools/scan-defects.js && node tools/gate-fit.js 1366 768 120
```

## 十、已知陷阱（条条踩过）

### 10.1 Shell 环境

| 陷阱 | 症状 | 解法 |
|---|---|---|
| Bash heredoc 吃反斜杠 | `\n` 变真换行、`\\` 变 `\` | 用 chr(92)/chr(10) 显式构造，或 Write 工具 |
| Git Bash 向 gh 传中文路径 | 上传文件名变成 `-.zip` | 先复制为 ASCII 文件名再上传 |
| SSH 到 github.com:443 瞬断 | `git push` 报 access rights | 等 15s 重试；或切 HTTPS via gh token |

### 10.2 构建与部署

| 陷阱 | 症状 | 解法 |
|---|---|---|
| data.js 尾部新增语句 | /api/bank 500 | server.py/worker.js 的 window.BANK= 截取改为行内提取 |
| 覆盖安装时 exe 被锁 | IOException 文件正由另一进程使用 | 先 taskkill 学考冲刺通.exe + pythonw.exe |
| --skip-build 用旧 site | 安装的不是最新 | 需要最新时去掉 --skip-build |
| wrangler OAuth 过期 | 要求登录 | 用 ~/.cloudflare/jiuyeke.env 中的 API token |
| pythonw 下 stderr 为 None | http.server 每请求空回复 | Handler.log_message 加 None 守卫 |

### 10.3 测试与前端

| 陷阱 | 症状 | 解法 |
|---|---|---|
| renderTabs 重绘丢徽章 | refreshBadges 抛 null | refreshBadges 已空安全，勿回退 |
| timeline 链尾 forEach | 赋值得到 undefined | 拆链：先赋值再 forEach |
| PK 右侧 id 小写 rBody/rSubmit | E2E 找不到元素 | 大小写敏感，右侧是 r 不是 R |
| E2E 驱动器 R 侧偶发竞态 | I3 偶发 R=null | 已加已提交等待分支，负载下偶发 |
| 迁移映射回摆环 | A→B→A 循环 | qid-migrate 自检淘汰 |
| apply-v5fix 丢 MIGRATE 行 | 迁移映射丢失 | 已修：写入时保留+扩展映射 |

### 10.4 题库内容

| 陷阱 | 说明 |
|---|---|
| 裸名词残片选项 | 「说法错误/正确」题干下，拆项变式截断产生「路由器。」式碎片；修复用 v10-frag-fix 流程 |
| 短陈述 vs 残片区分 | 完整短说法（如「1KB=1024B。」）是合法的，不要误修 |
| 解析与选项不匹配 | 解析可能来自同族他题（模板残留），修复时以学科事实为准 |
| 多个碎片在同一题 | 如 M7-sjvhv9 有 3 个碎片，逐个还原后校验唯一解 |

## 十三、安全红线

1. **绝不提交** `cloud/keys.json`（班级码+教师密钥）或 `data/` 目录（学生数据）
2. **绝不回显** 密钥/Token/API Key
3. **绝不直接改** `site/` 或 `dist/`（必须改 src/ 后重新构建）
4. **绝不改题干** 除非走 qid 迁移管线（否则学生记录断链）
5. **绝不删除** `window.XK_QID_MIGRATE` 行
6. **绝不绕过** apply-v5fix.js 的四零质检
7. **绝不把** 学生数据/密钥 写进 biji-notes/日志/截图
